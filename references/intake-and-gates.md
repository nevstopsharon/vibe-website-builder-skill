## 项目填空

请用户填写：

```text
我要为【人物/品牌/产品】制作【网站类型】。
目标用户是【用户】。
网站目标是【求职/展示作品/获得客户/品牌介绍/提供工具】。
用户最重要的三个动作是【动作】。
现有内容包括【图片、项目、文字、视频、链接】。
网站语言是【语言】。
预计每月更新【次数】，由【人数】维护。
是否必须在浏览器后台编辑：【是/否】。
是否需要登录、数据库、表单或搜索：【说明】。
是否商业项目：【是/否】。
目标上线时间是【日期】。
参考网站是【链接；没有可留空】。
明确不需要的功能是【功能】。
```

不要求真实内容齐全。缺失内容可用统一DEMO内容完成UI探索。

## 首次输出

在任何技术选择或代码前输出：

1. 网站的主要用户任务
2. 必须功能与暂缓功能
3. 页面结构
4. 每个页面需要的真实内容
5. MVP完成标准
6. 当前缺失素材
7. 风险与待确认事项

只有收到 `需求确认` 才继续。

## 三个代表页面

根据网站类型自动推荐3个最能覆盖结构差异的页面：

- 作品集：主页、项目列表/分类页、项目详情页
- 品牌/人物站：主页、内容/作品集合页、人物或内容详情页
- 内容站：主页、栏目页、文章页
- 活动站：落地页、日程/嘉宾页、报名或详情页
- Web App：登录/引导页、核心工作台、关键对象详情/编辑页

说明每页验证的结构和用户任务，收到 `页面确认` 后锁定。

## 状态文件

`project-state.json` 至少包含：

```json
{
  "project": "",
  "gates": {
    "requirements": false,
    "pages": false,
    "ui": false,
    "motion": false,
    "technology": false,
    "launch": false
  },
  "confirmed_phrases": [],
  "demo_items": [],
  "decisions": [],
  "change_requests": [],
  "release_exceptions": []
}
```

不得根据语气推断确认。

## 变更控制

确认后的修改使用：

```text
变更：
原值：
新值：
原因：
影响页面：
影响动效：
影响数据：
新增成本：
退回节点：
重新确认词：
```

如果只改已确认UI中的颜色，不影响动效和技术，则退回 `UI确认`；如果改变导航和核心用户流，则同时使后续动效与技术确认失效。
