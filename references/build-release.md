# 开发、验收与发布

## 目录

- 代表页面
- 静态页面
- 动效
- 阻断项
- 字节级发布验证

## 代表页面

选择能覆盖最多组件和响应式变化的页面。先完成静态内容和布局。

在以下宽度截图：

- 桌面：1440px
- 平板：1024px
- 手机：390px

逐项报告设计稿值、实现值和差异。检查溢出、断行、图片比例、焦点顺序和触控目标。

## 静态页面

- 使用真实内容或已登记DEMO。
- 建立统一设计变量。
- 主体排版不依赖大量绝对定位。
- 所有内容状态都有明确呈现。
- 静态页面通过后才添加动效。

## 动效

每次只实现一种已确认动效。该次提交不得同时改内容、布局或其他动效。验证桌面、手机、键盘、reduced-motion和性能。

## 阻断项

以下任一项存在时禁止发布：

- 未确认DEMO、pending或空白内容
- noindex未移除
- 页面、按钮、表单或链接失效
- 手机端溢出或内容被遮挡
- 主要流程无法使用键盘
- 缺少reduced-motion
- 图片缺尺寸、alt或来源
- 控制台错误
- 登录/数据库项目未验证RLS
- 密钥、原始素材或内部文档公开
- 本地发布包与线上文件不一致
- 缺少适用的404、robots、sitemap或canonical

用户只能明确接受一个具体风险，不能笼统说“忽略所有检查”。

## 字节级发布验证

- 从审计通过的本地发布包上传原始字节。
- 不得复制终端或工具截断后的文本作为发布文件。
- 使用明确允许列表，逐文件比较本地与线上SHA-256和字节数。
- 文本额外检查 `tokens truncated`、替换字符和常见乱码。
- 比较通过后，再对生产URL进行真实浏览器回归。
- 部署成功不是完成标准。

使用：

```powershell
py -3 scripts/audit_release.py --site-root <发布目录>
py -3 scripts/verify_deployment.py --site-root <发布目录> --base-url https://example.com --allowlist release-allowlist.json
```
